# 双机互联工作流

两台机器各跑一个 DSH，用 `dsh-peer-sync`（配置同步 + 远程投递）和 `dsh-device-mesh`（加密隧道 + 完整界面 portal）连起来。这套东西的难点不在配对，而在配对之后的判断：**谁在跑、东西存哪、怎么取回来、坏了看哪里**。

## 一、先判断"执行地"

**会话在哪台机器上创建，就在哪台机器上执行，产物就在哪台机器。** 这是全部判断的起点。

| 你看到的 | 实际在哪跑 | 文件在哪 |
|---|---|---|
| 「跨机同步」面板里标着「远程 · <名字>」的会话行 | 对端机器 | 对端机器的盘 |
| 面板里标着「本地」的行 | 本机 | 本机的盘 |
| 直接在本地 DSH 里新开的会话 | 本机 | 本机的盘 |
| 通过 portal 打开的界面里的一切 | 被打开的那台 | 那台的盘 |

两台之间**没有文件同步**。`peer-sync` 只同步三类东西：`cordis.patch.yml`、凭据引用（`cred:*`）、agent preset。会话内容、会话历史、工作文件都不会自动过去。

## 二、三条通道，各管各的

| 通道 | 能做什么 | 不能做什么 |
|---|---|---|
| **远程投递**（peer-sync） | 给对端某个会话发一句话，拿回它的回复；中断回合；归档 | 传文件、看界面、替对方点审批 |
| **Portal**（device-mesh） | 把对端的完整 DSH 界面搬过来：会话、文件、终端、审批弹窗 | 传文件到本地磁盘（看到≠拿到） |
| **文件直传**（本工具的 `mesh_send_file`） | 把一个文件送到对端指定目录，哈希校验 | 传目录（先打包） |

### 远程投递的关键行为

- 投递是"进某一行会话"，不是"跟当前对话说话"。选错行 = 进错房间。
- 新建的会话默认标题是「来自 <发起方名字> 的会话」，用它区分来源。
- 等待有预算（默认 300 秒）。**超时不等于失败**：任务还在对端跑，之后用「看最近结果」取。
- **对方卡在审批上时，远程调用无法解除**——审批只能由那台机器的所有者点。所以要么用 portal 过去点，要么把那台的新会话权限预设设成不需要批准。

## 三、产物存哪里

约定（可在 `AGENTS.md` 里固定）：

- 主工作区：一台机器上专门放活的目录，派过去的任务默认落这里
- 交付物：`<工作区>/输出/<任务名>/` 之类的固定子目录
- 用户说"存到外置盘"：外置盘的固定目录，并在回复里给出**绝对路径**

**外置盘的两个硬约束**：盘一拔，工作区就没了（新会话开不起来、旧会话读不到文件）；盘没挂载时不要静默失败，要明确说出来。

## 四、派活的标准流程

1. `mesh_status` 确认对端可达、没被撤销信任
2. 在面板里选中**目标会话行**（或新建一行），发指令
3. 指令里写清：**在哪台执行、工作目录的绝对路径、交付物要什么、放哪里**
4. 拿到回复后核对：如果看起来像"我准备做什么"的开场白，用「看最近结果」取最终答案
5. 长任务不要等：让它把结果写文件，回复里给路径

## 五、跨网络

同一 Wi-Fi 下，靠局域网地址就能连。出门后要靠 **Tailscale 之类的 mesh VPN**：

- 两台都连上，各自有 `100.x` 地址
- 服务的监听地址必须是 `0.0.0.0`（或 `auto` 选到了对的网卡），只绑内网 IP 的端口在 tailnet 上是连不上的
- 判断标准：在另一台机器上 `nc -z <tailnet IP> <端口>` 通不通

## 六、故障对照表

| 现象 | 先看这里 |
|---|---|
| 面板里对端「离线」 | 对端 DSH 是否在跑；`mesh_status` 看 `reachable` |
| 同步不动了 | 看 `~/.dsh/peer-sync/status.json` 的 `lastSyncAt` 与 `lastError` |
| 派活被拒 `remote-prompts-disabled` | 对端 `remotePrompts` 不是 `allow` |
| 派活被拒 `peer-revoked` | 对端或本机面板里点过「撤销」，需要恢复信任 |
| 投递成功但只拿到开场白 | 用「看最近结果」；或在服务端打"等到回合结束再返回"的补丁 |
| portal 打不开 | 配对凭据里是否含 tailnet 地址（配对发生在 Tailscale 连接之前的话就没有） |
| 重启后配置又被写回旧值 | 有些插件只在启动时读配置；要在**进程停止时**改文件，否则改完会被内存值覆盖 |

## 七、权限与风险（读之前先想清楚）

- `remotePrompts: allow` = 任何持有该对端 token 的人都能在那台机器上执行任务。**这是能力，也是暴露面。**
- 新会话默认「完全访问 + 不询问」能让无人值守跑通，但覆盖和删除都没有二次确认。
- 配对码/配对链接等同于密码，不要截图外发。
- 「撤销」是永久断开该对端的信任，不是临时开关。
